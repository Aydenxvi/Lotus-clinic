# LOTUS CLINIC — сценарий видеодемонстрации (2–3 минуты)

**Цель:** показать работодателю работающий продукт, а не просто прокрутить красивые страницы.

## Перед записью

1. Открой сайт в Microsoft Edge при масштабе 100% и разрешении 1920×1080 или 1600×900.
2. Подготовь отдельные окна браузера: публичная страница, аккаунт **вымышленного** пациента, тестовый аккаунт врача и главного врача. Выполни вход **до включения записи экрана**, чтобы пароли не попали в видео.
3. Убедись, что везде только вымышленные имена, телефоны, диагнозы и другие сведения. Закрой уведомления, личные вкладки и менеджер паролей.
4. Для записи: Windows 11 → **Пуск → Ножницы → Запись → Создать**; выдели область браузера и начни запись. Если в твоей версии «Ножниц» нет записи, подойдёт OBS Studio.
5. Если потребуется показать несколько ролей, переключайся между заранее подготовленными окнами или сделай отдельные короткие клипы и объедини их. Не показывай экран авторизации с вводом учётных данных.

## Таймлайн и текст озвучки

### 00:00–00:20 — Главная страница

**На экране:** главная страница, плавно прокрути первый экран, покажи меню.

**Озвучка:** «LOTUS CLINIC — мой full-stack проект для управления клиникой. Здесь пациент может выбрать врача и записаться на приём, а сотрудники — работать с расписанием и консультациями».

### 00:20–00:45 — Каталог и онлайн-запись

**На экране:** каталог врачей, карточка педиатра, страница выбора времени. Не обязательно создавать новую запись во время съёмки: достаточно показать интерфейс.

**Озвучка:** «Каталог и свободные слоты загружаются через Express API. Бронирование сохраняется в MySQL, а сервер предотвращает повторную бронь занятого времени».

### 00:45–01:10 — Кабинет пациента

**На экране:** заранее подготовленный кабинет вымышленного пациента: список приёмов и статус.

**Озвучка:** «У пациента есть отдельный кабинет: история записей, отмена и просмотр результатов завершённых консультаций. Доступ ограничен собственными данными пользователя».

### 01:10–01:45 — Кабинет врача

**На экране:** расписание, вымышленная запись, история болезни, форма диагноза и назначения. Не показывай настоящих медицинских сведений.

**Озвучка:** «Врач видит только свои приёмы. Он может оформить консультацию, сохранить диагноз, рекомендации, рецепт и направление на анализ. Информация связывается с конкретной записью в базе».

### 01:45–02:15 — Главный врач

**На экране:** список персонала, кабинеты, заявки на отгулы, лаборатория или аптечный склад. Достаточно двух-трёх коротких экранов.

**Озвучка:** «Главный врач управляет персоналом, кабинетами и клиническими процессами. Эти данные сохраняются на сервере и доступны с разных устройств при соответствующих правах».

### 02:15–02:40 — Код и проверка

**На экране:** GitHub README, схема архитектуры, папка миграций, затем результат `18/18 checks passed` (если показываешь терминал, убедись, что там нет секретов).

**Озвучка:** «Frontend написан на HTML, CSS и JavaScript; backend — Node.js и Express, база — MySQL с Prisma. Проект развёрнут на Render и Aiven. На опубликованной версии прошли 18 базовых проверок».

### 02:40–02:50 — Завершение

**На экране:** снова главная страница, подписи Live Demo и GitHub URL.

**Озвучка:** «Это учебный демонстрационный проект. Код, архитектура и рабочая версия доступны по ссылкам».

- Выложи видео на доступную тебе видеоплатформу или прикрепи к портфолио. Если не хочешь показывать закрытые разделы публично — держи видео по непубличной ссылке для работодателей.
- Добавь ссылку на видео в README только после проверки, что в нём нет паролей и данных реальных людей.

## Как добавить эти документы в GitHub

Распакуй два Markdown-файла из ZIP в папку `docs` твоего локального проекта. В PowerShell из корня проекта:

```powershell
git add docs/CASE_STUDY_RU.md docs/VIDEO_DEMO_SCRIPT_RU.md
git diff --cached --check
git commit -m "docs: add portfolio case study and demo script"
git push origin main
```

Эти действия не меняют сервер, сайт и MySQL.
